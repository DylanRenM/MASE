## Why

希望反复收听英文材料的 macOS 用户，目前缺少一个足够简单、离线、可控的本地文件听读工具。本变更交付“磨耳朵”的 macOS MVP，让用户能够从常见文档中提取英文内容，以系统语音持续循环朗读，并可靠地暂停、继续、停止和定时。

## What Changes

- 新增 `.txt`、`.docx`、文本型 `.pdf` 本地文件导入、20MB 限制及错误反馈。
- 新增严格英文过滤，只向 TTS 提交英文字母和必要空白。
- 新增循环播放、暂停/继续、独立停止以及慢/正常/快三档速度。
- 新增只累计实际朗读时间的 1–240 分钟可选定时器；留空时不限时。
- 新增百分比与段落进度展示。
- 新增播放期间源文件变化监控，并在 5 秒内询问是否重新加载。
- 新增确定性的会话状态机；应用重启后不恢复上次会话。
- 首版仅交付 macOS 13+ 原生应用，其他平台后续迭代。

## Capabilities

### New Capabilities

- `document-ingestion`: 选择、校验并解析 20MB 以内的 TXT、DOCX 和文本型 PDF。
- `english-content-filtering`: 过滤数字、标点、特殊字符和其他语言文字，仅保留英文字母与必要空白。
- `speech-playback-control`: 通过 macOS 系统英文语音执行播放、持续循环、暂停、继续、停止和三档速度控制。
- `active-reading-timer`: 支持 1–240 整数分钟或不限时，只累计实际朗读时间。
- `reading-progress`: 显示朗读百分比和当前英文段落/总段落数。
- `source-file-monitoring`: 播放期间在 5 秒内发现源文件修改，并处理重新加载或继续旧内容。
- `session-lifecycle`: 串行化用户操作，维护一致状态，并在停止、换文件和应用重启时按规则重置。

### Modified Capabilities

无。该项目目前没有已发布的 OpenSpec capability。

## Impact

- 技术平台：macOS 13 Ventura 或更高版本，原生 SwiftUI。
- 系统能力：macOS 系统 TTS；具体 API 适配在 Design L1 POC 中确认。
- 文档解析：PDF 优先使用系统 PDFKit；DOCX 解包/解析依赖必须通过独立 POC 后才能选定。
- 存储：不持久化文件内容、播放位置、计时或会话。
- 隐私：文档全程本地处理，不访问网络服务。
- 性能：20MB 以内文件不得造成崩溃或界面长期无响应。

## Out of Scope

- Windows、iOS、Android；
- 旧版 `.doc`；
- 扫描 PDF、OCR；
- 中文或其他语言朗读；
- 音色、发音人、自定义 TTS 引擎；
- 循环次数设置；
- 文本编辑、格式转换、多文件管理；
- 会话持久化、账户、云服务及网络同步。

## Stakeholders

- 产品确认者：项目用户；
- 主要用户：使用本地英文材料进行反复听读的 macOS 用户；
- 交付角色：MASE Agent 1（门禁）、Agent 2（需求）、Agent 3（设计与开发）、Agent 4（质量）。

## Success Criteria

- [ ] TXT、DOCX、文本型 PDF 的正常导入与朗读均有自动化验收覆盖。
- [ ] P0 E2E 场景 100% 通过。
- [ ] API/模块级契约测试 100% 通过。
- [ ] 暂停位置、暂停计时冻结、停止重置、定时到期及持续循环行为符合需求基线。
- [ ] 播放期间源文件修改在 5 秒内触发提示。
- [ ] 文档只在本地按数据处理，内容不得被执行或上传。
- [ ] 快速重复控制不会产生多个并行 TTS 会话或状态不一致。

## 操作流程

### 主流程

1. 用户启动应用，系统处于空闲状态。
2. 用户选择 `.txt`、`.docx` 或 `.pdf` 文件。
3. 系统验证格式、20MB 大小限制和可读性，提取并过滤英文内容。
4. 系统显示文件名、速度、可选定时和就绪状态，不自动播放。
5. 用户设置速度及可选的 1–240 分钟整数定时。
6. 用户点击播放，系统从文件开头朗读并更新进度。
7. 文件末尾到达后系统自动从头持续循环。
8. 用户可暂停、继续或停止；停止后保留文件并重置进度。

### 文件修改流程

1. 系统在播放期间监控已加载的源文件。
2. 外部修改发生后，系统在 5 秒内显示选择提示。
3. 用户选择重新加载时，系统解析新内容并从头播放。
4. 用户选择继续时，系统继续朗读内存中的旧内容。

## 系统测试用例

详细用例维护在 `docs/codes-projects/磨耳朵/测试用例集_2026-07-20-2.md`。Proposal 门禁至少覆盖以下需求族：

| 用例族 | 前置条件 | 操作 | 可验证结果 |
|--------|----------|------|------------|
| ST-DOC | 本地存在受支持或不受支持的文档 | 选择文件 | 正确接受 TXT/DOCX/文本型 PDF，拒绝 DOC、扫描 PDF、超限和损坏文件 |
| ST-FILTER | 文档含英文及其他字符 | 解析文档 | TTS 输入只含英文字母和必要空白 |
| ST-PLAY | 文件已就绪 | 播放至末尾 | 单一 TTS 会话持续循环，进度正确重置 |
| ST-PAUSE | 正在定时朗读 | 暂停后继续 | 位置保留，暂停时间不计入定时 |
| ST-STOP | 正在播放或暂停 | 点击停止 | TTS 与计时停止，进度归零，文件保持就绪 |
| ST-TIMER | 文件已就绪 | 输入定时并播放 | 只接受 1–240 整数；留空不限时；到期自动停止 |
| ST-SPEED | 空闲、就绪、暂停或播放 | 切换速度 | 非播放状态可切换，播放状态禁用，继续后应用新速度 |
| ST-MONITOR | 正在播放且源文件被修改 | 等待提示并选择 | 5 秒内提示；按选择重载新内容或继续旧内容 |
| ST-LIFECYCLE | 会话处于各业务状态 | 换文件、重复控制或重启 | 状态串行一致，换文件及重启按规则重置 |

## E2E 验收场景

### E2E-P0-001：TXT 主流程

- 用户故事：作为普通用户，我希望选择 TXT 并开始播放，以便循环收听英文内容。
- 前置条件：应用空闲；存在 20MB 以内、包含英文内容的 TXT。
- 操作步骤：选择文件；确认就绪；点击播放；观察进度；等待一次文件末尾。
- 预期结果：不自动播放；点击后从第一段朗读；显示百分比及段落数；末尾后从头继续。
- 优先级：P0。

### E2E-P0-002：DOCX 主流程

- 用户故事：作为普通用户，我希望直接朗读 DOCX 正文。
- 前置条件：存在可解析、包含英文正文的 DOCX。
- 操作步骤：选择文件；点击播放。
- 预期结果：正文英文内容被提取并正常朗读。
- 优先级：P0。

### E2E-P0-003：文本型 PDF 主流程

- 用户故事：作为普通用户，我希望朗读可复制文字的 PDF。
- 前置条件：存在包含可提取英文文本的 PDF。
- 操作步骤：选择文件；点击播放。
- 预期结果：英文内容被提取并正常朗读。
- 优先级：P0。

### E2E-P0-004：暂停、变速与继续

- 用户故事：作为普通用户，我希望暂停后调整速度并从原位置继续。
- 前置条件：文件正在按定时模式朗读。
- 操作步骤：暂停；等待；选择另一速度；继续。
- 预期结果：暂停期间进度与计时冻结；继续后从记录位置使用新速度朗读。
- 优先级：P0。

### E2E-P0-005：独立停止

- 用户故事：作为普通用户，我希望随时结束当前朗读并准备重头播放。
- 前置条件：系统正在播放或暂停。
- 操作步骤：点击停止；再次点击播放。
- 预期结果：首次停止立即终止并清除计时、进度归零且文件保留；再次播放从头开始。
- 优先级：P0。

### E2E-P0-006：有效朗读时间定时

- 用户故事：作为普通用户，我希望朗读满指定时长后自动停止。
- 前置条件：有效文件已就绪；设置合法整数分钟。
- 操作步骤：播放；暂停；等待；继续直至有效朗读时间到期。
- 预期结果：暂停时间不计入时长；到期后停止、进度归零且文件保持就绪。
- 优先级：P0。

### E2E-P0-007：严格英文过滤

- 用户故事：作为普通用户，我只希望听到文件中的英文字母内容。
- 前置条件：文件含英文、数字、标点、脚本字样和其他语言字符。
- 操作步骤：选择并播放文件。
- 预期结果：TTS 输入仅包含英文字母和必要空白；文件中的内容不会作为代码执行。
- 优先级：P0。

### E2E-P1-001：非法及不可读文件

- 用户故事：作为普通用户，我希望在文件无法朗读时获得明确反馈。
- 前置条件：分别准备 DOC、扫描 PDF、超过 20MB、损坏及空文件。
- 操作步骤：逐一选择文件。
- 预期结果：每种失败都有对应提示，系统不进入播放状态。
- 优先级：P1。

### E2E-P1-002：源文件修改

- 用户故事：作为普通用户，我希望正在播放的文件变化时决定是否更新内容。
- 前置条件：系统正在播放本地文件。
- 操作步骤：外部修改源文件；分别验证重新加载与继续旧内容。
- 预期结果：5 秒内出现提示；两条分支均符合需求。
- 优先级：P1。

### E2E-P1-003：换文件与重启重置

- 用户故事：作为普通用户，我希望换文件或重启时不会继承错误状态。
- 前置条件：系统处于暂停或播放状态。
- 操作步骤：选择新文件；另一次会话中强制关闭并重启应用。
- 预期结果：换文件清除旧会话并让新文件从头就绪；重启后回到空闲状态。
- 优先级：P1。

### E2E-P2-001：边界与竞争条件探索

- 用户故事：作为测试人员，我希望验证边界时序不会破坏状态一致性。
- 前置条件：准备特殊路径和短文本。
- 操作步骤：在循环边界触发定时；快速交替控制；选择特殊路径文件。
- 预期结果：无崩溃、无重复 TTS 会话，最终状态可预测。
- 优先级：P2。
