## Context

MASE 2.4 通过分阶段验证、Change Risk、Lite change、Gate DAG 和精确缓存解决了过重流程问题，但“为什么做这些取舍”分散在规则和课件中。同时，快速与高质量容易被误解为二选一：只报告门禁减少会鼓励降低质量，只报告全量发布耗时又看不到早反馈的收益。

## Goals / Non-Goals

**Goals:**

- 建立一句稳定、中文优先的顶层宗旨，并映射到可验证工程结果。
- 给出可用项目 evidence 重算的速度收益公式、样本要求和不确定性说明。
- 将宗旨与估算模型融合到规则、文档、Agent 指引和现有 2.4 课件章节。

**Non-Goals:**

- 不承诺所有项目均有固定提速百分比。
- 不为了速度删除硬门禁、影响链或发布验证。
- 不把代码行数、Token 数或 AI 输出量当作交付效率本身。
- 不修改 MASE 2.4.0 的运行时公共契约，不涉及任何采用项目。

## Decisions

### 1. 用一个宗旨和五个结果维度统一设计取舍

顶层表述使用“让 Agentic Coding 高效交付正确、健壮、优化且易于维护的代码”。五个结果维度不另起一套门禁，而是将现有机制映射到结果：

1. 高效交付：阶段等待、Token/上下文、重复执行和返工受控。
2. 需求正确：Spec、验收行为、契约和需求到证据追踪一致。
3. 运行健壮：异常、边界、并发、副作用、恢复和真实消费者路径经验证。
4. 质量优化：只对可测的性能、资源、安全或算法目标做有证据优化，不做无指标的过早优化。
5. 整洁可维护：去除重复、过度耦合、隐式契约、过大单元与过期代码，并用受保护测试防止重构误伤。

### 2. 速度收益分阶段计算

核心公式为：

```text
可手测等待收益 = 1 - T_new(dev_verified) / T_old(pre-hand-test)
发布认证收益 = 1 - T_new(candidate→release_ready) / T_old(candidate→release_ready)
质量调整后交付效率 = accepted_changes / (engineering_time + rework_time)
```

`T_new(dev_verified)` 只包含 development 时点的必需 gate 关键路径；`T_old(pre-hand-test)` 包含优化前被提前执行的开发、合并和发布 gate。开发与发布验证对象不同，不把后者延迟执行伪造成“被删除”的总成本。

### 3. 基线必须分层报告并显示样本限制

使用同一代码库、工具链和等价环境的结构化 evidence，分 gate 统计 p50/p90，至少 3 个样本才宣称 percentile。当前 MASE 示例使用 54 条自验证记录：

| 估算对象 | gate 观测中位数串行代理 | 说明 |
|---|---:|---|
| 2.4 开发验证 | 约 17.2s | 影响分析 + 差异契约 + 聚焦测试 |
| 合并验证 | 约 28.9s | API、集成、全链路冒烟等 |
| 发布认证 | 约 12.4s | 历史全量回归 + 回滚验证 |
| 旧式可手测前全部执行 | 约 58.4s | 三个时点合计 |

因此当前样本的可手测等待方向性收益约为 `1 - 17.2/58.4 = 70.5%`，可对外表述为“MASE 本仓当前低置信度样本约 71%”。影响分析、差异契约、影响复扫、全链路冒烟和回滚验证目前各只有 2 个样本，所以它们的正式 p50/p90 仍为 `unknown`。不将该结果外推为通用 SLA；采用项目必须用自身历史数据重算。

### 4. 课件融合而不新增脱节附录

宗旨放入开场、框架全景与六项原则之前的教学叙事；速度基线放入现有“效率治理/活动状态与证据索引”附近；课程总结回到五个结果维度。保持 66 页和现有版式，不为这一叙事额外堆页。

## Risks / Trade-offs

- [混合不同机器与历史命令会扭曲 p50] → 将 54 条记录标为本地示例，正式项目按工具链、环境、选择器和候选分组。
- [只看可手测等待可能掩盖发布总成本] → 必须并列发布认证耗时、返工率和逸出缺陷，不用单一百分比代替质量。
- [“优化代码”被理解为过早微优化] → 要求优化目标可测且不损害正确性、可读性和恢复能力。
- [宗旨只停留在口号] → 每个结果维度必须指向现有 Spec、测试、门禁或证据。

## Migration Plan

1. 增加宗旨和速度基线 Spec/文档。
2. 更新唯一规则源并再生成 IDE adapters。
3. 融合修改 2.4 课件结构源，重建可编辑 PPTX。
4. 运行文档一致性、课件、框架回归和边界验证。
5. 回滚时恢复文案与 2.4 课件；不涉及状态或数据迁移。

## Open Questions

- 无；速度数值始终随项目 evidence 更新，不作为固定产品承诺。
