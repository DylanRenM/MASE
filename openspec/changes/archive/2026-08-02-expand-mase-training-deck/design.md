## Context

当前培训课件由受保护 V1 的 37 页逐页更新生成，构建器、验证器和测试均硬编码 37。它适合概览，但影响链、GatePlan、测试选测、证据新鲜度和发布恢复缺少足够案例。`training/` 已默认排除于 Agent 上下文，因此扩页不会直接增加日常开发 Token；主要挑战是保持可编辑性、版式连续性和单一内容源。

## Goals / Non-Goals

**Goals:**

- 生成正好 66 页的中文优先完整培训课件。
- 保留 V1 文件字节不变，并复用其视觉语言和 Measures 标识。
- 新增页面保持文字、图形、流程和表格可编辑。
- 从一个 YAML 内容源维护完整内容，并以 `track` 支持未来精简输出。
- 自动验证页数、页码、章节、必要主题、禁用说法、画布和内容预算。

**Non-Goals:**

- 不把现有 37 页机械拆成 66 页。
- 不复制维护两套独立 PPT 文案。
- 不引入 Pilot、产品代码或产品案例数据。
- 不改变 MASE 运行时规则来迁就课件表述。

## Decisions

### 1. 采用 66 页交错章节化内容模型

课程分为八章：导入与原则、全景与角色、档位风险门禁、六步开发主线、影响链、测试与证据、BUG/评审/发布、案例演练与速查。每页只承担一个学习目标，概览页后就近插入机制或案例页，不允许把全部深讲内容堆在课件末尾。

### 2. 每页声明来源版式并按课程顺序克隆

构建器把 V1 仅作为只读模板库；66 页中的基础页和新增页都声明 `template_slide`，再按 YAML 顺序逐页克隆并替换内容。这样可以在不修改 V1 的前提下自由交错概览、机制、案例与演练，同时保留背景、图片、Measures 标识和可编辑对象。

### 3. 页码和验证改为动态总数

构建后统一重写形如 `NN / TOTAL` 的页码。验证器按每页的 `template_slide` 校验来源版式、标识数量、画布边界和可编辑文本，并额外检查关键主题的相对顺序与邻接关系。总页数来自 YAML `slide_count: 66`。

### 4. 单一内容源支持轨道标签

每页声明 `track: core|deep-dive|exercise`。本次必须生成 66 页 full；精简 deck 不是本轮强制交付，但构建 API 接受轨道过滤，为后续同源生成预留能力。YAML 仍是课件唯一人工维护内容源。

### 5. 培训内容以最终运行时事实为准

新增 GatePlan、上下文和测试去重页必须引用执行效率 change 的最终语义。英文 Schema 字段只在帮助操作时以中文说明加括号保留，标题和核心描述中文优先。

## Risks / Trade-offs

- [python-pptx 克隆关系复杂] → 只克隆无外部图表关系的已验证版式，并对图片、边界和文本可编辑性做自动测试。
- [66 页过长] → 使用轨道标签和章节页，完整课控制在 150～180 分钟；内容源可生成精简视图而不复制文案。
- [新增页文本过密] → 延续每页标题、四卡片或短流程模板，并设置字符/行长度预算。
- [框架行为仍在变化] → 课件 change 依赖效率 change，最后从当前规则和 Specs 做主题一致性校验。

## Migration Plan

1. 先让 source/schema 接受 `slide_count`、`track` 和 `template_slide`。
2. 改造构建器支持克隆页、动态页码和 66 页输出。
3. 扩写 YAML 内容并生成 PPTX。
4. 更新验证器、单测、分发检查和视觉分析。
5. 保留 V1 与旧输出备份策略；失败时可回退生成器和 37 页 YAML，不覆盖 V1。

6. 验证风险门禁、六步主线、影响链、测试证据和发布恢复的主题邻接关系，防止再次退化为后置附录。

## Open Questions
