# 设计文档：基准故事合理性评价

> MASE 2.0 阶段：Design | 关联 Agent：A1 (计划统管)
> 日期：2026-07-21

## 1. 概述

### 1.1 背景

当前基准故事上传仅做形式校验（Fibonacci 刻度、每档≥2条、标题描述非空），没有对基准故事的**内容质量**做评价。如果基准故事本身标定不一致（如同为5点的故事复杂度差异很大，或8点故事比5点还简单），后续的估算结果就不可靠。

### 1.2 目标

在基准故事上传确认入库前，增加**合理性评价**环节，检测两方面的质量问题：

- **梯度合理性**：复杂度是否随 Fibonacci 分值单调递增
- **归属一致性**：每条故事的特征向量是否与自身分值匹配

评价结果不影响形式校验，而是在校验通过后、确认入库前展示给用户。

### 1.3 关键设计决策

| 决策 | 选择 |
|------|------|
| 技术路线 | 统计筛查 + LLM 综合审查 |
| 阻断策略 | 分级：warning（提示）vs error（阻断入库） |
| LLM调用方式 | 全量一次性（小样本，成本可控） |
| 展示位置 | 嵌入上传预览区，不新增面板 |

## 2. 系统架构

### 2.1 流程位置

```
上传 Excel → 解析行 → 形式校验 → 特征提取 → 【合理性评价】→ 展示结果 → 用户确认入库
```

- 合理性评价在特征提取**之后**，依赖 10 维复杂度特征向量
- 形式校验和合理性评价独立运行，互不影响

### 2.2 新增组件

```
core/
  quality_evaluator.py    ← 新增：统计层评价器
services/
  baseline_service.py      ← 修改：parse_and_validate 中调用评价器
templates/
  index.html               ← 修改：预览区展示合理性格报告
```

## 3. 核心组件设计

### 3.1 QualityEvaluator（统计层）

`core/quality_evaluator.py`

```python
@dataclass
class QualityIssue:
    severity: str       # "warning" | "error"
    type: str           # "gradient" | "misalignment"
    message: str

@dataclass
class QualityReport:
    overall_score: int          # 0-100
    pass_: bool                 # 是否可以入库
    summary: str                # 统计层发现的异常描述
    issues_llm: str             # 可选：LLM 深度分析结果
    issues: list[QualityIssue]  # 问题列表
```

#### 3.1.1 梯度检测

**方法**：对每个分值的故事取特征向量质心，计算质心的 L2 模长（综合复杂度标量）。检查模长是否随分值单调递增。

```
1点模长 < 2点模长 < 3点模长 < 5点模长 < 8点模长 < 13点模长
```

**判定**：
- 单调递增 → 无问题
- 出现 1 处倒挂 → `warning`
- 出现 2+ 处倒挂 → `error`

#### 3.1.2 归属检测

**方法**：每条故事的特征向量分别与 6 个分值的质心计算欧氏距离。如果一条故事离自己标定分值的质心**不是最近**的，即为归属异常。

**判定**：
- 全部归属正确 → 无问题
- 异常比例 ≤ 20% → `warning`
- 异常比例 > 20% → `error`

#### 3.1.3 综合评分

```
总分 = 100
  - 梯度 error: -25, 梯度 warning: -10
  - 归属 error: -25, 归属 warning: -10
pass = (总分 >= 60 且无 error)
```

### 3.2 LLM 分析

因基准故事总数通常 12-24 条，直接全量发送给 LLM 做一次性综合审查。

**`{stories_summary}` 格式**：按分值分组的故事列表：

```
【1点】
  - S001: 修改按钮颜色（仅前端CSS调整）
  - S002: 添加提示文案（静态文本修改）
【2点】
  - S003: 新增搜索框（前端组件 + 单接口查询）
...
```

**Prompt 模板**：

```
你是一位故事点估算专家。请审查以下基准故事集的合理性，从两个角度：

1. 梯度合理性：同一分值的复杂度水平是否一致？不同分值间是否有合理的复杂度梯度？
2. 归属一致性：每条故事的点数标定是否合理？有没有明显标定错误的故事？

基准故事集：
{stories_summary}

统计层已发现的异常（供参考）：
{summary}

请用简洁的中文输出你的分析和建议。如果基准故事整体合理，明确说明"整体合理"。
```

**LLM 不可用时的降级**：`issues_llm` 设为空字符串 `""`，仅展示统计层结果。不阻断入库流程。

## 4. API 设计

### 4.1 修改 `POST /baseline/upload`

响应扩充 `quality_report` 字段：

```json
{
  "status": "ok",
  "rows": [...],
  "points_distribution": {...},
  "quality_report": {
    "overall_score": 82,
    "pass": true,
    "summary": "梯度合理，归属正常",
    "issues_llm": "整体合理。...",
    "issues": []
  }
}
```

`status: "error"` 时无 `quality_report`（形式校验未通过时不进行合理性评价）。

**注意**：LLM 调用会增加上传响应延迟（约 1-3 秒），前端需显示加载状态。

## 5. 前端展示

### 5.1 预览区扩展

在 `showPreview()` 函数中，点数分布之后追加合理性评估区块：

```
已解析 14 条故事  1点×2  2点×2  3点×2  5点×3  8点×3  13点×2

──── 合理性评估 ────  综合评分：82  通过 ✓

⚠ 梯度异常（注意）
  8点→13点的复杂度梯度出现倒挂

ℹ LLM 建议
  建议拆分"用户权限管理"（8点）...

                     [全量替换]  [追加合并]
```

### 5.2 阻断交互

- **pass=true**：绿色"通过 ✓"，确认按钮正常可用
- **pass=false（有 error）**：红色"不通过 ✗"，确认按钮禁用，提示"请修正基准故事后重新上传"
- **仅 warning 无 error**：黄色"通过（有改进空间）"，按钮可用

### 5.3 LLM 建议区

可折叠，默认展开。折叠按钮：`LLM 建议 ▾ / LLM 建议 ▸`

## 6. 测试策略

| 测试类型 | 覆盖内容 |
|----------|----------|
| 单元测试（QualityEvaluator） | 梯度检测正确返回 warning/error；归属检测正确计算异常比例；综合评分计算正确；`pass` 门槛逻辑 |
| 集成测试（/baseline/upload） | 响应包含 `quality_report` 字段；合理数据 pass=true；不合理数据 pass=false |
| 前端测试 | 评价区块在预览区正确渲染；阻断状态按钮禁用；LLM 建议折叠/展开 |

## 7. 不做什么

- 不改变现有形式校验逻辑
- 不做大样本下的复杂聚类分析（当前基准故事规模 12-24 条，简单规则已足够）
- 不提供"自动修正"功能（合理性评价是建议性的，修正由用户自行判断）
