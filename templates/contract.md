# {Capability} 风险驱动契约定义

> 从 spec.md 的 Gherkin 场景推导，定义本 Capability 的三层契约约束。
> API/公共协议硬性必做；模块/函数契约仅由业务不变量或高风险触发。
> 属性/模型测试仅在复杂输入空间、解析/序列化、数值边界、状态机、不可信输入、并发不变量或兼容性变更等场景评估；不适用时说明理由，不伪造属性。

## 一、API 级契约（硬性必做）

### 端点: POST /api/{resource}
- **前置条件**:
  - 请求体必须包含 {field1}，类型为 {type}，非空
  - {field2} 若存在，必须在 {min}-{max} 范围内
- **后置条件**:
  - 响应状态码 201
  - 响应体包含 id，类型为 integer，> 0
  - {resource} 已持久化到数据库
- **不变式**:
  - 同一 {unique_key} 不能创建两条记录
- **错误响应契约**:
  - 违反 {field1} 前置条件时返回 {status} 与稳定的 {error_schema/error_code}

### 端点: GET /api/{resource}/{id}
- **前置条件**: id 必须是正整数
- **后置条件**:
  - 若记录存在：状态码 200，响应体匹配 {schema}
  - 若记录不存在：状态码 404，响应体包含 error_code
- **不变式**: 无
